# 开发评审流程试用问题修复

本次试用是对已有 PR 的评审：代码和 PR 已存在，本轮没有新增提交，正确性与回归评审均通过，但流程仍停在“推送并创建或复用 MR”的审批。卡片未展示实际审批材料，无法判断批准后的动作。

## 问题与修复

| 问题 | 修复与完成条件 |
| --- | --- |
| 评审已有 PR 时，准备工具默认从目标基线创建工作区 | 预检记录官方 CLI 查询的 PR URL、源/目标分支及 head/base；固定工具在隔离分支检出实际 PR head，单独保留目标 base，支持同一准备步骤恢复。 |
| 无修改评审仍请求发布授权 | 固定工具从通过的评审证据、clean HEAD 和最新远端源分支生成交付计划。`reuse`/`none` 直接交付结论，无发布节点和审批；`update`/`create` 才进入审批。 |
| 隔离分支与原 PR 源分支不同，容易重复建 PR | 已有 PR 保留原 URL 和源分支；修复只能快进推送至原源分支，不能拿临时任务分支新建重复 PR。 |
| 审批卡只有固定提示，缺乏可决策信息 | 通用 `humanGate.contextFrom` 引用直接上游的必需字符串结果。卡片完整展示仓库、原 PR 或新建动作、分支、候选提交、变更/验证摘要、标题和正文，以及批准边界。 |
| 审批材料可能过期或被替换 | 材料绑定当前有效上游实例及 manifest 字节摘要；拒绝缺失、篡改、符号链接和过长材料。恢复缺失 wait 时重新验证材料，批准点击时再次核对，旧批准不能覆盖变更后的材料。 |
| 预设升级后，已登记流程因定义不一致而无法再次启动 | 只识别完整旧预设的规范化摘要，在原 owner、群范围内追加不可变新版本。自定义流程不覆盖，历史 run 的冻结定义不改写。 |

## 验证与边界

行为测试覆盖无修改直接交付、有修复等待审批、评审返工与次数耗尽、认证失败、真实临时 Git 仓库上的 PR head 准备、原分支复用/更新/新建计划、远端或工作树变化，以及审批材料恢复、失效和安全展示。原有卡片动作、普通审批与工作流恢复测试继续运行。

影响面是 v3 工作流的通用 DAG 校验、审批材料读取、恢复和飞书卡片，以及开发评审预设。CLI/PTY/普通话题处理不变；通用能力不识别预设名、仓库服务商或 CLI 类型。材料仅用于展示，不改变审批选项、审批人和已冻结的 gate。已有 host 节点继续使用其冻结输入审批机制。

历史运行不会因升级自动获批、推送或重写记录。修复对新版本流程生效。真实飞书点击仍须在部署后验收；Linux 自动化不代替 macOS 或外部业务部署验证。交互启动表单的全面声明式泛化属于后续工作，不包含在本次修复中。
